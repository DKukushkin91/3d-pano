# Proposal

Этап: **M4 · Многоуровневые панорамы** (см. [roadmap.md](../../roadmap.md)), первое из двух изменений
этапа: библиотека. CLI нарезки — следующее изменение `add-tile-cli`. Закрывает строки
[parity.md](../../parity.md):

- «Источники панорам»: многоуровневый тайловый куб.
- «Загрузка, память, события»:
  - приоритеты и отмена тайлов;
  - бюджет памяти.
- «Что использует neometria»: тайловый куб. Формат — собственный, neometria перенарежет тайлы под него
  (решение владельца).

## Why

Сейчас куб загружается целиком: шесть граней 4096 — это 64 МБ на грань в видеопамяти и десятки
мегабайт по сети, прежде чем сцена появится. neometria показывает сотни сцен «комната × ремонт» на
телефонах, поэтому без тайлов переезд невозможен. Многоуровневый куб грузит:

- сначала маленькую подложку;
- затем только видимые тайлы, по уровню нужной детализации;
- держит в памяти ограниченный пул.

## What Changes

- **Формат.** У кубического источника появляются `tileSize` и `levels` — размеры граней по уровням, —
  а `url` становится шаблоном с `{level}` (номер уровня с нуля), `{face}`, `{row}` и `{col}`. Уровень не
  больше `tileSize` — один тайл `0_0` на грань. Без `levels` куб работает как в M1.
- **Рендер.** Тот же полноэкранный шейдер на каждый пиксель. Тайлы лежат слоями общего пула текстур,
  таблица сопоставления говорит шейдеру, где какой тайл. Шейдер выбирает уровень по размеру пикселя и
  берёт более грубый, если нужного тайла нет. Смешивание M2 и будущие нелинейные проекции M6 работают
  без переделки.
- **Загрузка.**
  - Самый мелкий уровень грузится целиком и остаётся подложкой.
  - Для видимой области уровни грузятся по очереди от грубого к нужному текущему приближению и
    плотности экрана.
  - Порядок — от центра кадра к краям; ушедшие из кадра тайлы отменяются через `AbortSignal` загрузчика.
- **Готовность.** Тайловая сцена готова, когда загружены подложка и тайлы нужного уровня для кадра, с
  которым она появится: стартовый вид или текущий при `view: 'keep'`. Это момент смены сцены, `sceneReady`,
  `status: 'ready'` и `loadProgress: 1`. Остальные тайлы догружаются при поворотах без смены статуса.
- **Память.** Новая опция `tileCacheMegabytes` (по умолчанию 128) — один пул тайлов на просмотрщик,
  общий для всех сцен. Тайлы текущего кадра не вытесняются. `sceneCacheMegabytes` по-прежнему держит
  целые сцены и подложки тайловых.
- **Проявление.** Новая опция `tileFadeMs` (по умолчанию 200, `0` — сразу): тайл проявляется поверх
  более грубого уровня. Тайлы, нужные для готовности, видны сразу.
- **Предзагрузка.** `preloadScene(id, { view })` для тайловой сцены готовит подложку и тайлы кадра:
  по умолчанию для стартового вида сцены, с `view: 'keep'` — для текущего вида (другой ремонт той же
  комнаты).
- **Приближение.** Предел `maxPixelZoom` у тайлового куба считается по самому подробному уровню из
  описания сразу, а не по загруженному: приблизиться можно до предела, тайлы догрузятся.
- **Ошибки.** Не загрузилась подложка или тайл, нужный для готовности, — ошибка сцены, как сейчас
  (`resource`, `retry()`). Тайл после готовности при ошибке тихо остаётся на грубом уровне и
  запрашивается снова, когда опять попадёт в кадр.
- **Песочница:**
  - служебный скрипт `make-cube-faces.mjs` нарезает тайлы в новом формате из локальных 8K-панорам;
  - тайловые варианты сцен в демо-туре;
  - сценарии медленной сети, бюджета и предзагрузки.
- **Документация для интеграторов:** `docs/tour.md`, `docs/api.md`, `README.md`.

## Capabilities

### New Capabilities

- `multiresolution`:
  - формат тайлового куба и его проверка;
  - выбор уровня и видимых тайлов;
  - порядок загрузки, отмена и пул тайлов с бюджетом;
  - готовность и прогресс;
  - проявление;
  - ошибки тайлов;
  - опции `tileCacheMegabytes` и `tileFadeMs`.

### Modified Capabilities

- `panorama-sources`:
  - «Кубическая панорама из граней» относится к кубу без `levels`;
  - «Превью» — превью не тайловое, готовность тайловой сцены;
  - «Прогресс загрузки сцены» — доля изображений готовности тайловой сцены;
  - «Ошибка загрузки» — ошибки сцены только от изображений готовности.
- `camera-view`: «Ограничение увеличения по разрешению источника» — у тайлового куба плотность берётся
  по самому подробному уровню.
- `scene-navigation`:
  - «Предзагрузка сцены» получает опцию `view`;
  - «Предзагрузка в фоне» — тайлы кадра на экране важнее тайлов предзагрузки;
  - «Кэш сцен в видеопамяти» — у тайловой сцены считаются превью и подложка;
  - «Проверка опций смены сцены» — опции `preloadScene`.
- `hotspots`: «Предзагрузка при наведении» передаёт `view` цели.

## Impact

- Код:
  - чистая математика тайлов в `src/math/` или `src/tiles/`: выбор уровня, видимые тайлы, порядок,
    набор для готовности;
  - пул тайлов и таблица сопоставления — `src/render/`;
  - новый шейдер тайлового куба;
  - планировщик загрузок и тайловая сессия — `src/tiles/`;
  - навигатор — опция `view` у `preloadScene` и вид готовности;
  - опции просмотрщика.
- Публичный API:
  - поля `tileSize` и `levels` у `ICubeSource`;
  - опции `tileCacheMegabytes` и `tileFadeMs`;
  - второй аргумент `preloadScene`.

  Существующие сигнатуры совместимы.

- Тесты: новые `scripts/*.unit.mjs` на формат и проверку, выбор уровня и видимых тайлов, порядок и
  отмену, пул с LRU, готовность и прогресс.
- Зависимостей не добавляется. sharp уже стоит в песочнице для служебного скрипта.
- Документы проекта:
  - `roadmap.md` — M4 делится на `add-multiresolution` и `add-tile-cli`;
  - `parity.md` — строки тайлов и памяти.

## Вне рамок

| Не входит                                         | Почему / где будет                                                                 |
| ------------------------------------------------- | ---------------------------------------------------------------------------------- |
| CLI нарезки тайлов (пакет `3d-pano-tiles`)        | следующее изменение `add-tile-cli` (решение владельца)                             |
| Тайловые эквиректангулярные и плоские изображения | M7, по roadmap; механизм пула и выбора уровня из этого изменения станет их основой |
| Перекрытие тайлов (бордюр) против швов            | ступенька в один тексель на стыке незаметна на фотографиях; формат проще без него  |
| Манифест рядом с тайлами                          | решение владельца: пирамида описывается в туре                                     |
| Формат тайлов нынешней neometria (`l1`…`l4`)      | решение владельца: neometria перенарежет тайлы под формат библиотеки               |
| `prefers-reduced-motion` для проявления тайлов    | M6, вместе с остальными настройками движения                                       |
