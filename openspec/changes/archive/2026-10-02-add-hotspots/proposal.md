# Proposal

Этап: **M3 · Хотспоты и движение камеры** (см. [roadmap.md](../../roadmap.md)), второе изменение этапа
после `add-camera-motion`. Закрывает строки [parity.md](../../parity.md):

- «Хотспоты и интерфейс»:
  - точечные хотспоты-картинки и текстовые хотспоты — DOM-элементы;
  - хотспоты, лежащие в плоскости (CSS `matrix3d`; WebGL-поверхности — M5);
  - хотспоты в координатах мира;
  - наведение, клик и уход.
- «Сцены и переходы»: предзагрузка сцены — опция навигационного хотспота.
- «Анимации и автоповорот»: анимация свойств хотспотов — CSS хоста по состоянию элемента.
- «Что использует neometria»:
  - три хотспота на точку → один навигационный хотспот на полу;
  - увеличенные зоны нажатия на мобильных — CSS хоста;
  - глобальные колбэки `window.onHotspotClick`/`onHotspotHover` → события экземпляра;
  - пины товаров с rAF-циклом и проекцией в React → хотспоты хоста, которые позиционирует библиотека.

## Why

Сейчас хост может только сам проецировать точки через `project` в своём цикле кадров. neometria держит
ради этого React-оверлей с `requestAnimationFrame`, а навигационные точки на полу описывает тремя
хотспотами чужого движка со строковыми обработчиками и глобальными колбэками. Без хотспотов, которые
библиотека позиционирует сама, переход по точке и предзагрузка при наведении остаются на стороне хоста,
и переезд невозможен.

## What Changes

- **Хотспоты в туре.** У сцены появляется `hotspots`: `{ id, position, title?, target?, data?, anchor?,
plane? }`.
  - `position` — `TViewTarget`, как у `lookAt` и `project`: точка сферы или точка мира.
  - `target` — сцена и опции `showScene`.
  - `title` выводится через `textContent` и служит доступным именем.
  - `data` — произвольный JSON для отрисовки хоста.
- **Элемент хотспота из тура.** По умолчанию библиотека создаёт `<button type="button">` с `title` и
  data-атрибутами для CSS хоста; своих стилей не добавляет. Опция просмотрщика `renderHotspot`
  возвращает элемент хоста; в React — проп `renderHotspot`, возвращающий `ReactNode`.
- **Навигация.** Клик (а у кнопки — Enter и Пробел) отправляет `hotspotClick`, затем вызывает
  `showScene(target.scene, опции target)`. Обработчик может вызвать `preventDefault()` и перейти
  по-своему. Наведение и фокус запускают `preloadScene(target.scene)`.
- **События.** `hotspotClick`, `hotspotEnter`, `hotspotLeave` с `{ sceneId, hotspot }` — для хотспотов из
  тура. Наведение и фокус с клавиатуры считаются входом. React-пропсы `onHotspotClick`,
  `onHotspotEnter`, `onHotspotLeave`.
- **Хотспоты хоста.** `viewer.addHotspot({ element, position, scene?, anchor?, plane? })` возвращает
  объект управления. React-компонент `<Hotspot position scene? anchor? plane?>` рендерит детей
  порталом, позицию ставит библиотека — без перерисовок React.
- **Позиционирование.** Элемент оборачивается контейнером библиотеки, стили хоста не трогаются. Точка
  `anchor` элемента лежит в проекции `position`: по умолчанию центр, всего девять положений.
- **Хотспот в плоскости.** `plane: { width, facing?, spin? }` кладёт элемент в плоскость мира в
  перспективе через CSS `matrix3d`.
  - `width` — ширина элемента в единицах мира.
  - `facing` — куда смотрит его лицевая сторона: по умолчанию к центру панорамы, `pitch` 90 — лежит на
    полу.
  - `spin` поворачивает элемент в своей плоскости.
- **Видимость.** Хотспоты сцены показаны, пока сцена на экране. Пока грузится следующая, старые видны и
  работают. В момент появления новой сцены (начало смешивания) одни исчезают, другие появляются.
  Хотспоты хоста без `scene` видны всегда. Хотспот позади камеры не виден и не нажимается.
- **Клавиатура.** Хотспоты остаются в порядке Tab. Фокус с клавиатуры на хотспоте вне кадра плавно
  поворачивает к нему камеру (`lookAt`). Корень просмотрщика обрезает содержимое так, что фокус не
  прокручивает его.
- **Валидация.** `validateTour` строго проверяет хотспоты: `id` обязателен и уникален в сцене,
  `position` конечна, у направления ненулевая длина, `target.scene` есть в туре, опции перехода
  верны, `width` больше 0, `anchor` из словаря.
- **Песочница:**
  - навигационные точки на полу между сценами демо-тура;
  - текстовый хотспот;
  - пины хоста через `addHotspot` и `<Hotspot>`;
  - своя отрисовка через `renderHotspot`;
  - журнал событий и отмена перехода.
- **Документация для интеграторов:** `docs/tour.md`, `docs/api.md`, `docs/react.md`, `README.md`.

## Capabilities

### New Capabilities

- `hotspots`:
  - хотспоты из тура и хоста;
  - позиционирование, якорь, плоскость;
  - видимость и смена сцен;
  - навигация и предзагрузка;
  - события;
  - фокус с клавиатуры;
  - опция `renderHotspot` и её обновление, обрезка корня без прокрутки при фокусе.

### Modified Capabilities

- `tour-config`: структура сцены получает `hotspots`, новое требование — валидация хотспотов.
- `viewer-state-events`: типизированные события дополняются `hotspotClick`, `hotspotEnter`,
  `hotspotLeave`.
- `react-adapter`:
  - пропсы `renderHotspot`, `onHotspotClick`, `onHotspotEnter`, `onHotspotLeave`;
  - компонент `<Hotspot>`.

## Impact

- Код:
  - новый модуль `src/hotspots/`: типы, словарь якорей, слой DOM, хотспоты тура;
  - чистая математика размещения точки и плоскости в `src/math/`;
  - валидация хотспотов в `src/tour/`;
  - `src/viewer/create-pano-viewer.ts`: метод `addHotspot`, опция, шаг слоя в кадре. Файл уже на 259
    строках из 300, поэтому сборку придётся разделить.
  - `src/react/`: `<Hotspot>`, порталы для `renderHotspot`, новые пропсы.
- Публичный API:
  - поле сцены `hotspots`;
  - метод `addHotspot`;
  - опция `renderHotspot`;
  - три события;
  - словарь `EnumHotspotAnchor`;
  - типы хотспотов;
  - React-компонент и пропсы.

  Существующие сигнатуры не меняются.

- Тесты: новые `scripts/*.unit.mjs` на валидацию, проекцию точки и плоскости, видимость, порядок
  наложения, вход и уход, разрешение опций.
- Зависимостей не добавляется.
- Документы проекта: `parity.md` — строки хотспотов и того, что использует neometria.

## Вне рамок

| Не входит                                          | Почему / где будет                                                                |
| -------------------------------------------------- | --------------------------------------------------------------------------------- |
| Учёт глубины и WebGL-поверхности, видео-хотспоты   | M5 `add-3d-tours`: нужны позиции сцен и рендер поверхностей                       |
| Полигональные области (SVG)                        | M6, по roadmap                                                                    |
| Своя анимация свойств хотспотов (подсветка, пульс) | CSS хоста по data-атрибутам состояния: библиотека не меняет стили элементов хоста |
| Переход-движение к точке хотспота                  | M5 `add-3d-tours`; навигационный хотспот пока использует переходы M2              |
| События для хотспотов хоста                        | решение владельца: у своих элементов хост слушает DOM сам                         |
| Встроенное оформление хотспотов                    | своей системы UI-слоёв нет (roadmap); строгий CSP не позволяет внедрять `<style>` |
| Плавное растворение хотспотов при смешивании       | решение владельца: смена в момент появления сцены, проявление — CSS хоста         |
