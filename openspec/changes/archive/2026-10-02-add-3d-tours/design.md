# Design

## Context

- **Отрисовка.** Каждый слой рисуется полноэкранным шейдером: луч пикселя → направление в мире → выборка
  панорамы. Камера всегда в центре сцены, поэтому направление луча и есть направление выборки. Шейдеров
  три (эквиректангулярный, кубический, тайлового куба); общие функции куба вынесены в `cube-functions.ts`.
- **Смешивание.** Обе сцены рисуются в текстуры кадра, проход `composite-pass` смешивает их по весу.
  Кадр навигатора (`INavigatorFrame`) несёт текущую и предыдущую сцену, вес и замершую камеру предыдущей.
- **Камера** (`viewer/camera-state.ts`) отдаёт `frameCamera()` (оси и тангенсы) для отрисовки, `project`,
  `unproject` и слоя хотспотов. Точка `{ x, y, z }` сейчас — только направление из центра.
- **Смена сцены.** `present` применяет вид в момент появления новой сцены. Вид `keep` берёт текущий вид как
  есть.
- **Хотспоты тура.** Клик вызывает `showScene(target.scene, target)`, опции перехода проверяются тем же
  разбором, что у `showScene`.

Мотивация и объём — в [proposal.md](./proposal.md), поведение — в дельтах `specs/`.

## Goals / Non-Goals

**Goals:**

- Решения о геометрии проверяются контракт-тестами в Node:
  - модель «пол + сфера»;
  - точка и путь шага;
  - пересчёт между сценами;
  - сдвиги в кадре навигатора;
  - `project`/`unproject` и размещение хотспотов со сдвигом.
- Без сдвига камеры (вне шага) отрисовка, `project` и хотспоты дают ровно то же, что сейчас: шейдер не
  делает лишней работы, а тесты M1–M4 не меняются.

**Non-Goals:**

- WebGL-поверхности и глубина — второе изменение M5.
- Точная геометрия комнат (стены, карта глубины).

### Модель «пол + сфера»

Чистый модуль `math/scene-space.ts`; формулы повторяются в общем GLSL `shaders/space-functions.ts`.

- **Луч из камеры.** Камера в точке `o` (сдвиг от центра сцены), луч `d` (единичный). Пересечение со
  сферой радиуса `R`: `t_s = −(o·d) + √((o·d)² − (|o|² − R²))`. Пересечение с полом `y = −h` при `d.y < 0`:
  `t_f = (−h − o.y) / d.y`. Берётся меньшее положительное; без `h` — только сфера.
- **Выборка.** Цвет берётся по направлению `normalize(o + t·d)` — из центра сцены на точку модели.
- **Без сдвига.** При `o = 0` шейдер не считает пересечений: направление выборки — сам луч.
- **Точка модели в направлении.** Та же формула с `o = 0` — для точек сферы хотспотов и точки шага.
- **Пересчёт между сценами.** `toNewScene(p) = rotateYaw(p − c, turn)`, где `c` — центр новой сцены в
  координатах старой, а `rotateYaw` увеличивает `yaw` на `turn`. По позициям сцен:
  `c = rotateYaw(position_b − position_a, −heading_a)`, `turn = heading_a − heading_b`.

### Шаг в кадре навигатора

```
showScene(…, { transition: move }) ──► загрузка как у смены (кадр готовности — вид с доворотом)
появление ──► геометрия шага: точка (D155, D164), центр новой сцены и доворот (D163), радиусы (D161)
          ──► present(вид keep: yaw + доворот) ──► хотспоты новой сцены (D167)
кадр t ──► прогресс e = easing(t): сдвиг старой s·e, сдвиг новой toNewScene(s·e), вес смешивания e,
           сила размытия blur·sin(π·t), центр размытия ──► камера и слой хотспотов получают сдвиг новой
конец ──► сдвиги 0, промисы смены разрешаются
```

`INavigatorFrame` получает `space`: для текущей и предыдущей сцены — сдвиг, модель и поворот камеры
предыдущей сцены относительно живой (−доворот), плюс параметры размытия. Вне шага пространство пустое.

Уточнения при реализации (внутри согласованных решений):

- Кадр получает `move` (пространства обеих сцен, силу и точку размытия) и `previousYawShift` — обратный
  доворот, с которым живая камера рисует предыдущую сцену; он есть и у смешивания с `keep` между сценами с
  разным `heading`.
- Новый `showScene` во время шага ведёт себя как при смешивании (D169): промис шага сразу разрешается
  `false`, а сам шаг доигрывает, пока не появится новая сцена; её появление мгновенно завершает шаг.
- Хотспот, ведущий шагом, предзагружает цель с видом `keep` — тем, с которым она появится (D166, D171).
- `IFrameCamera`, `IProjectionCamera` и `ITileFrame` получают необязательное `space`: без него камера в центре,
  поэтому вызовы и тесты M1–M4 не меняются.

### Формулы в GLSL и TypeScript

- **Направление выборки** по лучу и сдвигу камеры (модель «пол + сфера») — `sceneDirection`.
- **Поворот по yaw** — `rotateYaw`.
- **Сила размытия** — `blur · sin(π · t)` (только в TS: в шейдер уходит готовое число).

## Risks / Trade-offs

- [Модель «пол + сфера» не знает стен: у близких стен параллакс неточный] → шаг короткий (0,5 с), а
  размытие и смешивание скрывают расхождение; точная геометрия — вне рамок.
- [Без `cameraHeight` пол «выпуклый»] → в документации `cameraHeight` рекомендуется для туров с шагом.
- [Радиальное размытие в проходе смешивания — 12 выборок на пиксель в течение 0,5 с] → только во время
  шага; на слабых устройствах `blur: 0` отключает его.
- [Смысл `keep` меняется у сцен с разным `heading`] → поле новое, у существующих туров его нет; у вариантов
  ремонта одной комнаты `heading` совпадает.

## Migration Plan

- Для ядра изменение обратно совместимо: новые необязательные поля, тип перехода и поле `IView.position`.
  Код, который создаёт объекты `IView` сам, должен добавить `position` — в библиотеке таких мест нет.
- neometria заменяет 3D-переход движка на `transition: { type: 'move', turn }` в `target` точек на полу; доворот
  комнаты из данных хотспота переходит в `turn` или в `heading` комнат.
