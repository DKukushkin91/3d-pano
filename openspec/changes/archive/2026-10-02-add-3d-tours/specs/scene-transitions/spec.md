# Spec Delta

## ADDED Requirements

### Requirement: Переход «шаг»

Переход `{ type: 'move', durationMs?, easing?, point?, turn?, blur? }` SHALL вести камеру по прямой от
центра текущей сцены к точке шага за `durationMs` (по умолчанию 500) с плавностью `easing` (по умолчанию
`quad-out`). Одновременно старая сцена растворяется в новой с весом `easing(t)`, а новая рисуется из той же
точки мира и в конце приходит в свой центр. `durationMs: 0` MUST быть равнозначен `cut`. Проверка:
контракт-тест кадров навигатора и сценарий песочницы.

#### Scenario: Шаг по умолчанию

- **WHEN** хост вызывает `showScene('bedroom', { transition: { type: 'move' } })`
- **THEN** шаг длится 500 мс с плавностью `quad-out` и размытием 0.5, а промис разрешается после его окончания

#### Scenario: Середина шага

- **WHEN** прошла половина времени шага длиной 2 к точке впереди
- **THEN** камера сдвинута вперёд на `2 · quad-out(0.5)` от центра старой сцены, а в новой сцене стоит в той же точке мира

#### Scenario: Поворот во время шага

- **WHEN** пользователь тянет камеру во время шага
- **THEN** вращаются обе сцены, а движение продолжается к той же точке

### Requirement: Точка шага

Точка шага SHALL браться: из `point` — точка мира как есть, точка сферы — точка модели в её направлении;
при клике по хотспоту — из его `position`; если у обеих сцен есть `position` — центр новой сцены;
иначе — точка модели в центре кадра. Кроме случая с `position` сцен, камера MUST идти по горизонтали, на
высоте своего центра. Проверка: контракт-тест разрешения точки.

#### Scenario: Клик по метке на полу

- **WHEN** пользователь нажимает хотспот на полу `{ x: 0.2, y: -1.5, z: -2.5 }` с `target: { scene: 'balcony', transition: { type: 'move' } }`
- **THEN** камера идёт в точку `{ x: 0.2, y: 0, z: -2.5 }` над меткой

#### Scenario: Комнаты с позициями

- **WHEN** у `kitchen` `position: { x: 0, y: 0, z: 0 }`, у `hall` `position: { x: 3, y: 0.4, z: 1 }`, и хост вызывает `showScene('hall', { transition: { type: 'move' } })`
- **THEN** камера идёт ровно в центр `hall`, в том числе на 0.4 вверх

#### Scenario: Без геометрии

- **WHEN** у сцен нет `position`, а хост не передаёт `point`
- **THEN** камера идёт вперёд, к точке модели в центре кадра

### Requirement: Доворот новой сцены

Направление с `yaw` `Y` в текущей сцене SHALL иметь в новой сцене `yaw` `Y + turn`. Без `turn` доворот —
разность `heading` текущей и новой сцены (без `heading` — 0). Если у сцен нет `position`, центр новой сцены
MUST считаться лежащим в точке шага. Проверка: контракт-тест пересчёта между сценами.

#### Scenario: Комнаты с разным heading

- **WHEN** у кухни `heading: 0`, у спальни `heading: 90`, пользователь смотрит на `yaw` 90 кухни и делает шаг в спальню
- **THEN** после шага `yaw` равен 0: камера смотрит в то же направление мира

#### Scenario: Явный доворот

- **WHEN** хост передаёт `turn: -30`, а пользователь смотрит на `yaw` 10
- **THEN** после шага `yaw` равен −20

### Requirement: Размытие шага

`blur` от 0 до 1 SHALL задавать силу радиального размытия от экранной точки, к которой идёт камера.
Размытие MUST быть наибольшим в середине шага и отсутствовать в начале и в конце; `blur: 0` его отключает.
Проверка: контракт-тест силы размытия и сценарий песочницы.

#### Scenario: Шаг без размытия

- **WHEN** хост передаёт `blur: 0`
- **THEN** кадры шага не размыты

#### Scenario: Конец шага

- **WHEN** шаг закончился
- **THEN** новая сцена видна без размытия

## MODIFIED Requirements

### Requirement: Словари переходов

Библиотека SHALL экспортировать словарь `EnumTransitionType` (`cut`, `blend`, `move`) и тип его значений.
Поле `transition.type` MUST принимать как строки, так и константы словаря. Проверка: контракт-тест
значений и проверка типов в песочнице.

#### Scenario: Константа или строка

- **WHEN** хост передаёт `type: EnumTransitionType.Blend` или `type: 'blend'`
- **THEN** оба вызова компилируются и ведут себя одинаково
