# Design

## Context

- **Отрисовка.** Каждый слой рисуется полноэкранным проходом шейдера на каждый пиксель
  (`render/renderer.ts`). Кубический шейдер:
  - выбирает грань и тайл по направлению луча (`cubeFaceFromDirection`);
  - берёт MIP по отношению углового размера пикселя к угловому размеру текселя;
  - читает слой из текстуры-массива, где лежат все тайлы шести граней одного изображения.

  Слои описываются `TLayerDrawing` и рисуются по порядку: превью, затем основной источник.

- **Сессия сцены** (`viewer/scene-session.ts`) держит слой превью и основной слой. Её `load()`
  разрешается, когда основной источник целиком в видеопамяти, а статус и плотность для `maxPixelZoom`
  считаются по загруженным слоям.
- **Навигатор** (`navigation/*`) считает сессию готовой по флагу записи `isComplete` и держит готовые
  сессии в кэше `sceneCacheMegabytes` по `byteSize()`. Вид появления он разрешает в `present` — в момент
  появления сцены, а не в момент вызова `showScene`.
- **Загрузка изображения.** `loadImage(url, signal)` — загрузчик хоста или стандартный, с повторами. Отмена
  через `signal` уже поддерживается.
- **Служебный скрипт.** `examples/playground/scripts/make-cube-faces.mjs` режет грани куба из локальных
  8K-панорам через sharp (зависимость песочницы).

Мотивация и объём — в [proposal.md](./proposal.md), поведение — в дельтах `specs/`.

## Goals / Non-Goals

**Goals:**

- Решения о тайлах проверяются контракт-тестами в Node без WebGL — это чистые функции:
  - разбор пирамиды и URL тайлов;
  - нужный уровень и видимые тайлы;
  - набор готовности;
  - очередь с приоритетами и отменой;
  - пул с LRU.
- Нетайловые сцены рисуются и грузятся как раньше: тот же шейдер, сессия и тесты.
- В кадре без изменений вида, размера и загрузок видимые тайлы не пересчитываются.

**Non-Goals:**

- Перекрытие тайлов, тайловые эквиректангулярные изображения, CLI — см. «Вне рамок» в proposal.
- Статистика тайлов в публичном API (D146).

### Пирамида и таблица сопоставления

- Уровень `l` размером `S_l` режется на `n_l = max(1, S_l / tileSize)` тайлов на сторону грани; размер
  тайла — `min(S_l, tileSize)`.
- Уровень 0 — подложка в своей текстуре сцены (D141). Уровни 1…N−1 — в пуле.
- Таблица сопоставления сцены — текстура `RG16UI`, по записи на тайл уровней 1…N−1:
  - запись тайла `(l, face, row, col)` лежит по номеру `offset_l + face·n_l² + row·n_l + col`;
  - `R` — номер слоя пула + 1 (`0` — тайла нет);
  - `G` — прозрачность проявления, 0…65535.
- Шейдер получает `offset_l`, `S_l` и число уровней униформами-массивами длиной 10 (D134).

### Шейдер тайлового куба

```
direction, pixelAngle ← луч пикселя (как в кубическом шейдере)
face, (s, t) ← cubeFaceFromDirection(direction)
L ← neededLevel(pixelAngle, s, t)            // D135
color ← 0; remaining ← 1
для l = L … 1:
  entry ← table[offset_l + tileIndex(face, s, t, n_l)]
  если тайл есть: color += remaining · alpha · sample(pool, entry.layer, pointInTile)
                  remaining *= 1 − alpha; если remaining ≈ 0 — выход
color += remaining · textureLod(base, face, MIP по подложке)
```

Тайлы с полной прозрачностью закрывают всё ниже, поэтому в обычном кадре цикл заканчивается на первом
найденном тайле. Слой рисуется одним проходом, как нынешний кубический, и так же работает в смешивании
сцен.

### Формулы в GLSL и TypeScript

Каждая формула есть в шейдере и в чистом модуле `tiles/tile-math.ts` и покрывается контракт-тестами:

- **Угловой размер пикселя:** `max(|d(direction)/dx|, |d(direction)/dy|)`; в TypeScript — угол между
  лучами соседних пикселей буфера.
- **Угловой размер текселя уровня:** `(2 / S_l) / (1 + s² + t²)` — та же формула, что уже стоит в
  кубическом шейдере.
- **Нужный уровень:** самый мелкий `l` с `texelAngle_l ≤ pixelAngle`, иначе `N − 1`.
- **Тайл и точка в нём:** `faceCoordinates = (s, t) / 2 + 0.5`;
  `tile = min(floor(faceCoordinates · n_l), n_l − 1)`; `pointInTile = faceCoordinates · n_l − tile`.
- **Номер записи в таблице:** `offset_l + face · n_l² + row · n_l + col`.

### Загрузка

```
сцена принята к показу или предзагрузке ──► кадр появления (D139) ──► набор готовности:
    тайлы подложки + видимые тайлы нужного уровня (D137, D138), урезанные по пулу (D140)
очередь (D136) ──► loadImage(url, signal) ──► проверка размера (D145) ──►
    подложка: запись в текстуру сцены │ уровень ≥ 1: слой пула, запись в таблицу
все тайлы готовности на месте ──► load() разрешается ──► смена, sceneReady, ready
кадр: вид, буфер или загрузки изменились ──► видимые тайлы всех уровней до нужного (D124) ──►
    новые в очередь, ушедшие из кадра — abort(), отрисованные — отметка LRU
```

- Навигатор передаёт сессии вид появления: `load(appearance)`. Запись кэша считается готовой для смены,
  только если сессия готова для этого вида; нетайловые сессии вид игнорируют.
- Вид появления для `'keep'` и объекта считается при вызове `showScene` или `preloadScene` так же, как
  в `present`: те же правила наложения и ограничения новой сцены.
- Тайл, который нужен и сцене на экране, и предзагрузке, запрашивается один раз (общий URL в пуле).

## Risks / Trade-offs

- [Пул 128 МБ выделяется целиком, даже если кадру нужно 30 тайлов] → хост уменьшает
  `tileCacheMegabytes`; на телефоне кадр 4096-уровня занимает 60–90 тайлов, так что бюджет близок к
  нужному; рост удвоением — альтернатива в D140.
- [Ступенька в один тексель на стыке тайлов без перекрытия] → на фотографиях незаметна; перекрытие —
  вне рамок.
- [Без MIP в пуле — лёгкая рябь при уменьшении до 2×] → выбор уровня на пиксель держит уменьшение в
  этих пределах; подложка с MIP закрывает широкий FOV.
- [Сетка с шагом 32 пикселя может пропустить узкую полоску тайла на краю кадра] → полоска уже 32
  пикселей видна с детализацией грубее и догружается, когда станет шире.
- [Разные `tileSize` в одном туре запрещены] → CLI режет одним размером; другой размер — повод для
  второго пула, если появится реальная потребность.
- [`MAX_ARRAY_TEXTURE_LAYERS` меньше расчёта] → пул ограничивается лимитом устройства (не меньше 256
  по WebGL2), кадр остаётся грубее.

## Migration Plan

- Для ядра изменение обратно совместимо: новые необязательные поля источника, опции и аргумент
  `preloadScene`. Куб без `levels` работает как в M1.
- neometria перенарезает тайлы в формат D122 (CLI — в `add-tile-cli`) и описывает пирамиду в туре:
  `url`, `tileSize: 512`, `levels: [512, 1024, 2048, 4096]` и имена граней `f`, `r`, `b`, `l`, `u`, `d`.
