# Design

## Context

- **Кадр.**
  - Каждый слой панорамы рисуется полноэкранным треугольником: луч пикселя, сдвиг камеры шага M5,
    выборка.
  - Вне перехода кадр идёт прямо в canvas.
  - Во время смешивания и шага каждая сцена рисуется в свою текстуру кадра, а `composite-pass` сводит их
    по весу и размывает.
  - Контекст создаётся с `depth: false`; у текстур кадра буфера глубины нет.
- **Хотспоты.**
  - Слой хотспотов (`hotspots/hotspot-layer.ts`) держит DOM-элементы в оверлее над canvas: точка —
    `translate3d`, плоскость — `matrix3d` (`math/hotspot-placement.ts`).
  - Сдвиг камеры учитывает `anchorFromCamera`: точка сферы лежит на модели сцены, плоскость растягивается
    на её расстояние.
  - Хотспоты тура пересоздаются в момент появления новой сцены (D97, D167): старые элементы убираются
    сразу.
- **Загрузка.** Изображения сцен идут через `loadImage` (`loader` хоста, `retry`, `createImageBitmap`).
  Тайлы, не загрузившиеся после готовности, не дают событий `error`.
- **Цикл кадров** работает по требованию: кадр рисуется только после `requestRender()`.
- **Сессии сцен** (`ISceneSession`) не знают `id` своей сцены — кадр навигатора отдаёт сами сессии.

Мотивация и объём — в [proposal.md](./proposal.md), поведение — в дельтах `specs/`.

## Goals / Non-Goals

**Goals:**

- В Node контракт-тестами проверяются:
  - геометрия поверхности (углы, якорь, сдвиг камеры) — против того же расчёта, что ставит DOM-элемент;
  - порядок отрисовки;
  - выбор поверхностей кадра при смене сцен;
  - учёт текстур;
  - проверка `surface`.
- Без поверхностей кадр рисуется так же, как сейчас: проход поверхностей пуст, тесты M1–M5 не меняются.
- Хотспоты без `surface` ведут себя как раньше: DOM-слой не меняется, кроме атрибута у хотспотов с
  поверхностью.

**Non-Goals:**

- Нажатие по поверхности лучом: зона нажатия — DOM-элемент.
- Нелинейные проекции и WebXR — M6 и M8; проход поверхностей пока прямолинейный.

### Поверхность в кадре

Каждый кадр:

1. **Выбор поверхностей.** Слой поверхностей отдаёт два набора: для текущей сцены и, во время перехода,
   для предыдущей (D188). Записи хотспотов тура, убранных в момент появления, помечены «уходящими» и
   рисуются только с предыдущей сценой. Когда сцена перестала быть ни текущей, ни предыдущей, их
   текстуры и видео освобождаются.
2. **Геометрия.** Для каждой записи с загруженным источником `math/surface-geometry.ts` считает
   прямоугольник относительно камеры кадра (со сдвигом шага):
   - точка — `anchorFromCamera`;
   - оси — `planeBasis`;
   - размер — `width × width · h / w` источника, умноженный на масштаб точки сферы;
   - угол «верх-лево» — по долям якоря.

   Порядок — по убыванию расстояния до точки.

3. **Проход поверхностей.** После слоёв панорамы, в тот же буфер (canvas или текстуру кадра своей
   сцены): одна программа, два треугольника на поверхность из `gl_VertexID`, униформы — угол, две оси,
   оси камеры, тангенсы обзора, текстура.

### Уточнения реализации

Мелкие решения внутри согласованного дизайна, принятые при реализации.

- **Типы.** Варианты `THotspotSurface` и `TAddHotspotSurface` помечают чужой источник как `?: never`, чтобы
  TypeScript не принимал `{ image, video }` сразу.
- **Атрибут.** `data-pano-surface` стоит, только пока у хотспота есть и `surface`, и `plane`, — то есть пока
  поверхность рисуется (D183, D192).
- **Ключи источников.** URL входит в ключ вместе с видом (`image:` или `video:`); элементы и `ImageBitmap`
  — ключи сами по себе.
- **Обратная сторона.** Задняя сторона поверхности не отсекается и видна зеркально — как у элемента в
  плоскости с CSS `matrix3d`.
- **Отрисовка.** `drawFrame` получает сцену (`camera`, `drawings`, `surfaces`) и буфер объектами вместо
  пяти позиционных аргументов.
- **Загрузка.** Создание тайлов, графики и загрузчика изображений вынесено в `viewer/viewer-rendering.ts`,
  чтобы `create-pano-viewer.ts` остался в пределах 300 строк. `loadImage` принимает параметры
  `createImageBitmap` (`decode`): картинки поверхностей декодируются с предумноженной альфой.

## Risks / Trade-offs

- [Буфер глубины у canvas есть всегда, даже без поверхностей: +4 байта на пиксель] → размер буфера уже
  ограничен `maxPixelRatio` и `renderScale`; текстуры кадра с глубиной живут только во время перехода.
- [Пересекающиеся полупрозрачные поверхности смешиваются неточно: порядок по точке хотспота, а не
  попиксельно] → прозрачные пиксели отбрасываются; меткам и табличкам этого хватает.
- [Браузер может запретить автозапуск даже без звука (режим энергосбережения iOS)] → виден первый кадр;
  управление — через `<video>` хоста.
- [Картинки и видео других доменов без CORS-заголовков нельзя залить в WebGL] → предупреждение в
  документации; картинки и так идут через `fetch`.
- [`ImageBitmap` хоста с непредумноженной альфой даст тёмную кайму] → документация: создавать с
  `premultiplyAlpha: 'premultiply'` или по умолчанию.
- [Замерший кадр предыдущей сцены (смешивание с `view: 'scene'`) не обновляет видео до конца смешивания]
  → смешивание короткое; живая камера (`keep`, шаг) рисует видео каждый кадр.
- [Без `requestVideoFrameCallback` цикл кадров не останавливается, пока видео играет] → метод есть во
  всех актуальных браузерах; запасной путь только для старых.
