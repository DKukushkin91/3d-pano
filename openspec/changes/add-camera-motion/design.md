# Design

## Context

Камера просмотрщика (`viewer/camera-state.ts`) хранит вид и проводит любое изменение через
`constrainView`. Двигать её умеют три источника:

- `setView` хоста — мгновенно;
- жесты и клавиатура (`controls/*`) — шагом в кадре отрисовки, который `input.step(timeMs)` вызывает
  из `renderFrame`;
- появление новой сцены — через `present` навигатора: `camera.resetScene` плюс
  `input.handleSceneChange(keepMotion)`.

Цикл отрисовки работает по требованию: кадр рисуется, пока функция кадра возвращает `true`. Функции
плавности и их проверка (`resolveEasing`) готовы с M2, как и правило «время перехода отсчитывается с
первого кадра» (`blendFrame`). `create-pano-viewer.ts` занимает 237 строк из 300.

Мотивация и объём — в [proposal.md](./proposal.md), поведение — в дельтах `specs/`.

## Goals / Non-Goals

**Goals:**

- Логика поворота проверяется контракт-тестами в Node без DOM и WebGL. Время приходит извне
  (`step(timeMs)`), камера — настоящая `createCameraState`.
- Шаг движения камеры — отдельный механизм рядом с вводом, на который в M6 ляжет автоповорот.
- Поворот не добавляет перерисовок React: снимок состояния не меняется.

**Non-Goals:**

- Движение камеры в мире (M5) и анимация крена.
- Плавное прерывание (торможение) при вводе пользователя: камера останавливается сразу и отдаётся
  жесту.

### Контракт публичного API (добавления)

```ts
export interface ILookAtOptions {
  /** Поле обзора в конце поворота, в градусах в текущем режиме FOV. Без него FOV не меняется. */
  fov?: number;
  /** По умолчанию 900; 0 — сразу. */
  durationMs?: number;
  /** По умолчанию `cubic-out`. */
  easing?: TEasing;
  signal?: AbortSignal;
}

export type TViewTarget = ISpherePoint | IDirection;

interface IPanoViewer {
  // …M1–M2
  project: (point: TViewTarget) => IProjectedPoint | null; // было ISpherePoint | IDirection — тот же тип
  lookAt: (target: TViewTarget, options?: ILookAtOptions) => Promise<boolean>;
}
```

### Жизнь поворота

```
lookAt(target, options) ──► проверка аргументов (RangeError синхронно, D79)
                        ──► destroy был / signal уже отменён / ввод идёт (D75) → false, вид не меняется
                        ──► запомнить направление вращения по yaw (D80), прервать прежний
                            поворот (его промис → false), погасить инерцию
                        ──► цель: точка → yaw/pitch (D81), fov из опций или текущий,
                            провести через ограничения сцены (D73)
                        ──► durationMs 0 или цель = текущий вид → поставить вид, true (D78)
                        ──► кадр: startMs ??= timeMs (D83); вид = кривая(easing(t)), через ограничения
                        ──► t ≥ 1 → точный итоговый вид, промис → true
прерывание: ввод, setView, новый lookAt, abort(), destroy, появление сцены без keepMotion → false
появление сцены с keepMotion → пересчитать цель и кривую (D84), время окончания то же
```

Кривая поворота: `view(t) = start + (target − start) · easing(t)` для `pitch` и `fov`. Для `yaw` берётся
разность по кратчайшей дуге (цель ровно сзади — по D80), а при диапазоне `bounds.yaw` оба конца разворачиваются около центра
диапазона — тогда прямая между ними лежит внутри него. Каждый кадр вид снова проходит через
`constrainView`, поэтому перелёт у плавностей `back` и `elastic` не выводит камеру за ограничения.

Формул, живущих и в GLSL, и в TypeScript, изменение не добавляет: поворот меняет только вид, шейдеры не
трогаются.

## Risks / Trade-offs

- [Интерполяция по углам у полюсов идёт «дугой», а не по прямой на сфере] → в турах цели лежат далеко
  от полюсов; так же работают привычные анимации `yaw` и `pitch`, в том числе в neometria (D82).
- [Линейное гашение разницы при `keepMotion` добавляет постоянную скорость] → при смене ремонта с `keep`
  разница почти нулевая; заметна она только при `view: 'scene'` вместе с `keepMotion`, где рывок
  неизбежен (D84).
- [Колесо прерывает поворот, даже если пользователь хотел только приблизить] → это выбор владельца:
  пользователь главнее анимации (D70).
- [`create-pano-viewer.ts` растёт] → поворот живёт в своём модуле, в сборке — только связка.

## Migration Plan

- Изменение обратно совместимо: новый метод и тип. Код M1–M2 компилируется без правок.
- neometria заменяет `use-focus-pin-camera` (опрос по таймеру и ручной кратчайший путь) на
  `await viewer.showScene(...)`, затем `viewer.lookAt(точка пина, { signal })` в эффекте.
