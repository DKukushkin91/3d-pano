# Spec Delta

## Purpose

Как хост узнаёт о том, что происходит в просмотрщике: снимок состояния с подпиской для фреймворков и
типизированные события для отдельных происшествий.

## ADDED Requirements

### Requirement: Снимок состояния

`getSnapshot()` SHALL возвращать неизменяемый объект `{ sceneId, status, loadProgress, error }`, где
`status` — `loading`, `ready` или `error`. Пока состояние не изменилось, MUST возвращаться тот же объект.
Вид камеры в снимок не входит. Проверка: контракт-тест.

#### Scenario: Повторное чтение

- **WHEN** хост дважды вызывает `getSnapshot()` без изменений между вызовами
- **THEN** оба вызова возвращают один и тот же объект

#### Scenario: Вращение не меняет снимок

- **WHEN** пользователь вращает загруженную сцену
- **THEN** объект снимка не меняется

### Requirement: Подписка на изменения

`subscribe(listener)` SHALL вызывать `listener` после каждого изменения снимка и возвращать функцию
отписки. `subscribe` и `getSnapshot` MUST работать как отдельные функции без привязки контекста — их
можно передать прямо в `useSyncExternalStore`. Проверка: контракт-тест.

#### Scenario: React-хост

- **WHEN** хост вызывает `useSyncExternalStore(viewer.subscribe, viewer.getSnapshot)`
- **THEN** компонент перерисовывается при смене статуса и прогресса загрузки и не перерисовывается при вращении

### Requirement: Типизированные события

`on(name, handler)` SHALL подписывать обработчик на событие и возвращать функцию отписки. События:
`sceneLoadStart` и `sceneReady` с `{ sceneId }`, `viewChange` с `{ view }`, `error` с `{ error }`.
Проверка: контракт-тест эмиттера и проверка типов.

#### Scenario: Подписка и отписка

- **WHEN** хост подписался на `sceneReady`, а затем вызвал функцию отписки
- **THEN** обработчик больше не вызывается

### Requirement: События не теряются при создании

Просмотрщик MUST NOT отправлять события синхронно внутри `createPanoViewer`: обработчики, подписанные
сразу после создания, SHALL получить все события загрузки стартовой сцены, включая ошибки валидации.
Проверка: сценарий песочницы.

#### Scenario: Ошибка видна сразу

- **WHEN** хост создаёт просмотрщик с невалидным туром и сразу подписывается на `error`
- **THEN** обработчик получает ошибку `invalid-tour`

### Requirement: Описание ошибок

Ошибка SHALL быть объектом `{ code, message, url?, issues? }` с кодом из списка: `webgl-unavailable`,
`invalid-tour`, `resource-failed`, `invalid-image`. `url` указывается для ошибок изображений, `issues` —
для ошибок тура. Проверка: проверка типов и контракт-тест.

#### Scenario: Ошибка изображения

- **WHEN** не загрузилась грань куба
- **THEN** ошибка содержит код `resource-failed` и URL грани

### Requirement: Изоляция обработчиков

Исключение в обработчике события или подписчике SHALL NOT прерывать работу просмотрщика и вызов остальных
обработчиков; оно MUST передаваться в `reportError` окружения. Проверка: контракт-тест.

#### Scenario: Падающий обработчик

- **WHEN** один из двух обработчиков `sceneReady` бросает исключение
- **THEN** второй обработчик всё равно вызывается, а исключение попадает в `reportError`
