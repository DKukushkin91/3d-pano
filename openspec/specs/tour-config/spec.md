# tour-config Specification

## Purpose

Формат тура — JSON-совместимых данных, которые описывают сцены, их источники, начальный вид и
ограничения, — и правила, по которым библиотека его проверяет и дополняет значениями по умолчанию.

## Requirements

### Requirement: Структура тура

Тур SHALL быть объектом `{ startScene?, defaults?, scenes }`, где `scenes` — непустой массив сцен
`{ id, title?, source, preview?, view?, limits?, hotspots?, position?, heading?, cameraHeight? }`, а
`defaults` может содержать `view`, `limits` и `cameraHeight`. Хотспот сцены — `{ id, position, title?,
target?, data?, anchor?, plane? }`. Тур MUST быть сериализуемым в JSON: функций, элементов DOM и кода в нём
нет. Проверка: контракт-тест `validateTour`.

#### Scenario: Минимальный тур

- **WHEN** тур содержит одну сцену с `id` и `source`
- **THEN** `validateTour` не находит проблем, а просмотрщик показывает эту сцену

#### Scenario: Тур из ответа сервера

- **WHEN** тур получен как результат `JSON.parse` ответа сервера
- **THEN** он принимается без преобразований

#### Scenario: Хотспоты в JSON

- **WHEN** сцена из ответа сервера содержит `hotspots` с `target` и произвольным `data`
- **THEN** тур принимается без преобразований, а `data` доходит до `renderHotspot` и событий как есть

#### Scenario: Квартира в мире

- **WHEN** сцены из ответа сервера содержат `position`, `heading`, а `defaults` — `cameraHeight`
- **THEN** тур принимается без преобразований, и переходы «шаг» идут по этим данным

### Requirement: Стартовая сцена

Просмотрщик SHALL показать сцену с `id`, равным `startScene`, а если `startScene` не задан — первую
сцену массива. Проверка: контракт-тест разрешения стартовой сцены.

#### Scenario: Стартовая сцена не задана

- **WHEN** тур не содержит `startScene`
- **THEN** показывается первая сцена из `scenes`

### Requirement: Наложение значений по умолчанию

Итоговые настройки вида и ограничений сцены SHALL получаться наложением по полям: умолчания библиотеки,
затем `tour.defaults`, затем `view` и `limits` сцены. Проверка: контракт-тест.

#### Scenario: Сцена переопределяет направление

- **WHEN** `tour.defaults.view` задаёт `fov: 80`, а сцена — только `yaw: 35`
- **THEN** итоговый вид сцены — `yaw` 35, `fov` 80, остальные поля — умолчания библиотеки

### Requirement: Умолчания библиотеки

Если поле не задано ни в туре, ни в сцене, библиотека SHALL использовать: `yaw` 0, `pitch` 0, `roll` 0,
`fov` 90, `fovMode` `max`; ограничения `fov` [30, 120], `maxPixelZoom` 2, `bounds` `auto`.
Проверка: контракт-тест.

#### Scenario: Пустые умолчания

- **WHEN** ни тур, ни сцена не задают вид и ограничения
- **THEN** итоговый вид и ограничения совпадают с умолчаниями библиотеки

### Requirement: Валидация тура

Функция `validateTour(value)` SHALL возвращать массив проблем `{ path, message }` и пустой массив для
корректного тура. Она MUST проверять: тип и непустоту `scenes`, уникальность и непустоту `id`,
существование `startScene`, тип источника и превью, наличие `{face}` в шаблоне куба, схемы URL,
числовые диапазоны вида и ограничений. Проверка: контракт-тест.

#### Scenario: Повторяющийся идентификатор

- **WHEN** две сцены имеют `id` `kitchen`
- **THEN** `validateTour` возвращает проблему с путём `scenes[1].id`

#### Scenario: Несуществующая стартовая сцена

- **WHEN** `startScene` равен `hall`, а такой сцены нет
- **THEN** `validateTour` возвращает проблему с путём `startScene`

### Requirement: Невалидный тур при создании просмотрщика

Если тур, переданный в `createPanoViewer`, невалиден, просмотрщик MUST NOT бросать исключение: он SHALL
перейти в статус `error` с категорией `tour`, кодом `invalid-tour` и списком проблем и сообщить об этом
событием `error`. Проверка: сценарий песочницы.

#### Scenario: Сломанный тур с сервера

- **WHEN** хост передаёт тур без `scenes`
- **THEN** страница продолжает работать, снимок содержит ошибку `invalid-tour` с проблемой по пути `scenes`

### Requirement: Словари значений тура

Библиотека SHALL экспортировать словари `EnumSourceType`, `EnumCubeFace`, `EnumFovMode`, `EnumBoundsMode`
и типы их значений. Поля тура MUST принимать как строки, так и константы словарей: тур из `JSON.parse`
проходит проверку типов без приведения. Проверка: контракт-тест значений и проверка типов в песочнице.

#### Scenario: Константа или строка

- **WHEN** одна сцена задана с `type: EnumSourceType.Cube`, другая — с `type: 'cube'`
- **THEN** обе компилируются и одинаково проходят `validateTour`

### Requirement: Валидация хотспотов

`validateTour` SHALL проверять хотспоты сцен строго, как остальной тур: `hotspots` — массив; `id`
непуст и уникален в сцене; `position` — конечные `yaw` и `pitch` или ненулевые конечные `x`, `y`, `z`;
`title` — строка; `target.scene` есть в туре, а опции перехода верны, как у `showScene`; `anchor` из
словаря; `plane.width` больше 0, углы `facing` и `spin` конечны. Любая проблема делает тур
невалидным. Проверка: контракт-тест.

#### Scenario: Переход в несуществующую сцену

- **WHEN** у хотспота третьей сцены `target.scene` — `attic`, а такой сцены нет
- **THEN** `validateTour` возвращает проблему с путём `scenes[2].hotspots[0].target.scene`

#### Scenario: Повторяющийся id хотспота

- **WHEN** в одной сцене два хотспота с `id` `door`
- **THEN** `validateTour` возвращает проблему с путём `scenes[0].hotspots[1].id`, а одинаковые `id` в разных сценах допустимы
