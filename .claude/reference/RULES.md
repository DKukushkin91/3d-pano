# RULES

Правила кода 3d-pano. Нарушения блокируются проверками (`pnpm check`) или ревью. Принципы, из которых они
следуют, — в [openspec/constitution.md](../../openspec/constitution.md).

## 1. Структура библиотеки

- **Точки входа.** `src/index.ts` — публичное ядро, `src/react.ts` — React-адаптер, `src/internal.ts` —
  служебная точка для контракт-тестов (в `package.json#exports` не публикуется). Новая публичная точка
  входа — только через изменение OpenSpec.
- **Чистое отдельно от побочного.** Модули математики и логики (углы, векторы, проекции, ограничения
  вида, анимации, выбор тайлов, валидация конфигурации) не импортируют модули DOM, WebGL и сети.
  Обратное разрешено. Так логику можно проверить `node --test` без браузера.
- **Безопасный импорт.** На уровне модуля нет обращений к `window`, `document`, `navigator`,
  `matchMedia`, WebGL. Всё браузерное начинается внутри фабрик, создающих просмотрщик.
- **Ноль зависимостей рантайма в ядре.** Новая зависимость любого вида — только по согласованию с
  пользователем. В пакете и его peer-зависимостях — только MIT/BSD/ISC/Apache-2.0; инструменты
  разработки вне пакета могут быть под LGPL (конституция, I.6).
- **Адаптеры тонкие.** React-код только связывает компонентную модель с публичным API ядра и не
  содержит логики панорамы.
- **Ресурсы освобождаются.** Всё, что создаёт подписку, таймер, наблюдатель, WebGL-объект или запрос,
  возвращает функцию очистки или регистрируется в общем списке очистки владельца. `destroy()` обязан
  вернуть DOM в исходное состояние.

## 2. Именование

| Сущность        | Формат                                                                   | Пример                                     |
| --------------- | ------------------------------------------------------------------------ | ------------------------------------------ |
| Type alias      | `T` + PascalCase                                                         | `TPanoramaSource`, `TEasing`               |
| Interface       | `I` + PascalCase                                                         | `IViewState`, `ITileRequest`               |
| Перечисление    | `Enum` + PascalCase — словарь `as const`, тип значений — `T` + то же имя | `EnumSourceType` + `TSourceType`           |
| Функция-фабрика | `create` + PascalCase                                                    | `createTileCache`, `createRenderLoop`      |
| Предикат        | `is`/`has`/`should` + PascalCase                                         | `isCubeSource`, `hasWebGl2`                |
| Хук             | `use` + camelCase                                                        | `useViewerSnapshot`                        |
| Обработчик      | `handle` + PascalCase                                                    | `handlePointerDown`                        |
| Константа       | `UPPER_SNAKE_CASE` с единицами                                           | `MAX_PIXEL_RATIO`, `TILE_FADE_DURATION_MS` |
| Файл, папка     | `kebab-case`                                                             | `view-limits.ts`, `tile-cache/`            |

- **Перечисления — словари `as const`, а не `enum`.** Везде, где значение — одно из фиксированного
  набора строк, объявляется словарь и тип его значений:

  ```ts
  export const EnumSourceType = { Equirect: 'equirect', Cube: 'cube' } as const;
  export type TSourceType = (typeof EnumSourceType)[keyof typeof EnumSourceType];
  ```

  В коде библиотеки сравниваем только с константами словаря (`EnumSourceType.Cube`), хост может писать и
  строку — JSON тура с сервера проходит без приведения. `enum` номинален и запрещён при
  `erasableSyntaxOnly`, `const enum` ломает хосты с `isolatedModules` — оба не используются.

- **Имена несут смысл.** Однобуквенные имена запрещены (`e`, `i`, `t`, `a`, `b`) — включая счётчики и
  параметры колбэков. Исключение — `x`, `y`, `z`, `w` как компоненты векторов и экранных координат.
  Сокращения `btn`, `msg`, `cfg`, `tex` запрещены — пишем `button`, `message`, `config`, `texture`.
  Общепринятые аббревиатуры предметной области допустимы: `fov`, `url`, `gl` (WebGL-контекст);
  прочие сокращения раскрываем (`pixelRatio`, а не `dpr`).
- **Углы в именах указывают единицы, если неочевидно:** `yawDegrees`/`yawRadians` во внутренних
  функциях, где встречаются оба вида. В публичном API единицы всегда градусы, и суффикс не нужен.

## 3. Математика и WebGL

- Публичные углы — в градусах, внутренние — в радианах. Перевод — только функциями `toRadians` /
  `toDegrees` на границе публичного API.
- Система координат мира одна на всю библиотеку: X — вправо, Y — вверх, Z — вперёд (направление
  `yaw = 0, pitch = 0`). Yaw растёт вправо, pitch — вверх.
- Каждая формула, которая есть и в GLSL, и в TypeScript (проекции, раскладка граней куба), пишется
  с одинаковыми именами функций в обоих местах, и TS-версия покрывается контракт-тестом. Экранные
  координаты хотспотов обязаны совпадать с картинкой.
- Шейдеры — GLSL ES 3.00 в `.ts`-модулях как именованные строковые константы. Без минификации и без
  склейки строк из кусочков, кроме подстановки выбранной проекции через `#define`.
- WebGL-объекты создаются и удаляются парно в одном модуле-владельце. Потеря контекста — штатная
  ситуация, а не исключение.
- В цикле отрисовки не создаются временные объекты, если можно переиспользовать заранее созданные
  буферы (`Float32Array`, векторы-приёмники). Читаемость важнее экономии одной аллокации вне кадра.

## 4. React-адаптер

Правила pin для React действуют и здесь:

- **Инлайн-стрелки в JSX-пропсах запрещены** — именованные обработчики, `useCallback` для
  параметризованных.
- **`useEffect` — только синхронизация с внешней системой.** Просмотрщик — внешняя система, поэтому
  создание/уничтожение и передача опций в `viewer.update()` — законные эффекты. Производное состояние
  считается в рендере, подписки — через `useSyncExternalStore`.
- **Разметка на сервере и клиенте совпадает.** Поведенческие пропсы не меняют HTML; ветвления по
  `typeof window` в рендере запрещены.
- Порядок кода в компоненте: контекст → локальный стейт → библиотечные хуки (`useRef`, `useMemo`) →
  собственные хуки → обработчики → эффекты → `return`.
- Инлайн-стили — только для runtime-значений, которые классом не выражаются (позиционирование
  хотспотов); обоснование — в JSDoc ближайшего экспорта.

## 5. Качество кода

- **Не больше 300 строк в файле** (`max-lines`, считаются все строки). Упёрся в лимит — раздели модуль по
  ответственности, а не ужимай форматирование.
- **Без переусложнений.** SonarJS в `pnpm lint` следит за когнитивной сложностью функций (не выше 15),
  вложенностью управляющих конструкций и выражений, вложенными тернарниками, схлопываемыми `if`,
  одинаковыми функциями и ветками, дублями строк. `max-depth` — не глубже 4 блоков. Сработало правило —
  упрощай: ранний выход, вынос функции, таблица соответствий вместо цепочки условий.
- **KISS и YAGNI.** Не добавляем опции и абстракции, которых нет в спецификации. Обобщаем после
  третьего повторения.
- **Никаких магических значений.** Числа и строки — именованные константы рядом с местом
  использования или в модуле констант слоя.
- **Запрещены** `any`, необоснованный `as`, `@ts-ignore`, `@ts-expect-error` и отключение правил
  oxlint. Допустимо: `unknown` + сужение, `as const`, `satisfies`.
- **Сужение типов — предикатами.** Данные извне (конфигурация тура, ответ загрузчика) проходят через
  `isFoo(value): value is TFoo` или валидатор, а не через `as`.
- **Ранний выход вместо вложенности.** `if` всегда со скобками и на отдельных строках, даже для одного
  выражения.
- **Функция делает одно.** «И» в имени (`loadAndUpload`) — сигнал разделить.
- **Ошибки программиста — синхронно.** Неверная опция → `RangeError`/`TypeError` с префиксом
  `3d-pano:` и именем опции. Ошибки окружения и сети → событие `error` и отклонённый промис, без
  падения страницы.

## 6. Комментарии

Разрешён только JSDoc `/** … */` на русском непосредственно над `export`. Он объясняет «почему»:
нетривиальный инвариант, ограничение браузера, выбор формулы. Если хочется объяснить «что делает
код» — переименуй. Инлайн `//`, блочные `/* */` и комментарии внутри GLSL запрещены. Проверяет
`pnpm check:comments`.

## 7. Код, сгенерированный языковой моделью

Перед коммитом любой AI-код обязан:

1. Проходить `pnpm check` полностью.
2. Соответствовать конституции, спецификации действующего изменения и пунктам 1–6.

Отдельно:

- **Не придумывать молча.** Решение, которого нет в запросе, спецификации или коде, — вопрос
  пользователю до реализации (см. AGENTS.md, правило 1).
- **Не отключать правила.** Не получается исправить нарушение — объясни почему и оставь решение
  пользователю.
- **Никаких TODO с обещаниями.** Либо сделано, либо задача остаётся открытой в `tasks.md`.
- **Никаких неиспользуемых импортов, переменных, экспортов.**
- **Чистая комната.** Не открывать код проприетарных движков, не воспроизводить чужие имена API в `src/` (проверяет
  `pnpm check:clean-room`), не пересказывать чужую документацию близко к тексту.

## 8. Документация

- Публичный API описан в `README.md` и `docs/` на английском. Изменение публичного API без правки
  документации — незавершённое изменение.
- Каждый TS/TSX-пример в `README.md` и `docs/` компилируется против собранного пакета — это проверяет
  `pnpm check:docs`. Библиотечные символы пример импортирует сам; значения хоста (`container`, `tour`,
  `viewer` и т. п.) объявлены в `examples/doc-snippets/globals.d.ts`. Новая заглушка — только если без неё
  пример станет нечитаемым. JSON-примеры туров прогоняются через `validateTour` в контракт-тесте.
