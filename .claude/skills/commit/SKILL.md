# Commit Changes

Формат: `<type>[(scope)][!]: <описание>`.

- Типы: `feat`, `fix`, `chore`, `docs`, `refactor`, `test`, `perf`, `build`, `ci`, `style`, `revert`.
- Область — модуль библиотеки на английском: `core`, `render`, `view`, `controls`, `sources`,
  `hotspots`, `transitions`, `react`, `playground`, `openspec`, `docs`.
- Описание — **на русском**, повелительное наклонение, со строчной буквы, без точки в конце:
  `feat(view): добавить ограничения поля зрения по охвату источника`.
- Тело (через пустую строку) объясняет «почему» и перечисляет конкретные изменения маркерами.
- Ломающее изменение — `!` после типа/области и футер `BREAKING CHANGE: …`.

Сначала определи стиль по сигналам репозитория, а не по памяти.

## Steps

### 1. Проверить staged-изменения

```bash
git status
git diff --cached
```

Если ничего не добавлено в индекс и пользователь не просил добавить файлы — скажи об этом и остановись.
В рамках `/opsx:apply` агент сам добавляет файлы одного логического шага.

Перед коммитом убедись, что `pnpm check` зелёный (или что шаг не затрагивает проверяемые файлы).
Никогда не добавляй в индекс файлы проприетарных движков и `scripts/clean-room.local.json`.

### 2. Сигналы стиля (параллельно)

- `git log -10 --format="%s"` — последние заголовки;
- `git log -5 --format="%B%n---%n"` — как пишутся тела;
- наличие `commitlint`-конфигов и `.husky/commit-msg`.

### 3. Один коммит — одна мысль

Если в индексе несколько несвязанных изменений, предложи разбить их на несколько коммитов.
Спецификация и код одного шага могут идти вместе; инфраструктура и фича — раздельно.

### 4. Создать коммит

```bash
git commit -F - <<'EOF'
feat(scope): описание на русском

Почему это изменение нужно.

- конкретное изменение с путём или идентификатором
- ещё одно
EOF
```

Если хук отклонил сообщение — исправь причину и повтори один раз. `--no-verify` запрещён.

## Rules

- **Никаких трейлеров** `Co-authored-by`, `Made-with`, `Generated with …` — ни для Claude, ни для
  других инструментов, даже если они встречаются в истории.
- Никаких эмодзи.
- Заголовок до 72 символов.
- Работаем в `main`; `git push` — только по явной просьбе пользователя.
